# 구현 역량 점검

2026-09-27 코드와 테스트를 기준으로 확인했습니다. 구현의 존재, 공개 데모에서의 실행, 운영 성능의 검증을 구분합니다.

## 1. Agent 오케스트레이션 및 운영

**구현됨**

- `src/orchestration/router.ts`: 질문과 대화 문맥을 파싱하고 필요한 작업을 선택합니다. Jev 판단이 불확실하면 LLM planner로 전환하며, 모델이 없으면 규칙을 사용합니다.
- `src/orchestration/graph.ts`, `orchestrator.ts`, `runner.ts`: 조건별 실행 계획, Portfolio·Evidence 병렬 실행, 결과 합성, 일부 실패의 수집과 대체 답변을 구현합니다.
- `src/agents/portfolio-agent.ts`, `evidence-agent.ts`: AI SDK `generateText`에 도구를 전달하며, 4~6단계의 호출 제한과 구조화 출력을 사용합니다.
- `src/services/conversation-store.ts`: SQLite에 대화를 저장하고 최근 12개 메시지를 사용합니다. assistant 메시지는 요약과 권고를 뽑아 문맥을 줄입니다. 자동 장기 요약이나 벡터 메모리는 없습니다.
- `src/orchestration/tracer.ts`: 단계와 도구별 시간·상태·토큰·추정 비용을 저장합니다. SSE로 진행 상황을 전달합니다.

**공개 데모의 범위**

API 키가 없는 실행에서는 규칙 라우팅·금융 계산·메모리·Trace를 체험합니다. LLM 에이전트와 Function Calling은 생략됩니다. 해당 기능의 실행 근거는 모델을 연결한 영상과 실제 Trace로 추가해야 합니다. 멀티 에이전트 구현을 공개 데모의 템플릿 응답과 혼동하지 않습니다.

**아직 검증하지 않은 부분**

단일 Machine, 로컬 SQLite, 프로세스 내부 캐시·토큰 공유를 사용합니다. 부하 테스트, p95/p99·오류율·처리량 목표, 분산 큐, 공용 요청 제한, 수평 확장 및 장애 복구 검증이 없습니다. 익명 쿠키는 로그인이나 인증된 사용자 격리를 제공하지 않습니다. 따라서 “대규모 사용자 환경에서 안정적으로 서빙했다”는 주장에는 추가 구현과 측정이 필요합니다.

## 2. Eval 및 응답 개선

**구현됨**

- 30문항 golden dataset으로 여덟 가지 라우팅 결과를 검사합니다. `route(..., null, ...)`로 모델을 제외한 규칙 경로를 평가합니다.
- 정책·시뮬레이션·정규화·사용자별 대화 저장·Toss 토큰 처리 등을 회귀 테스트합니다.
- 검증 규칙과 선택적 Jev 판단으로 원칙 충돌, 예측 단정, 근거 부족 등을 점검합니다. 임계값을 넘으면 LLM Critic이 문제를 지적하고 Synthesizer가 한 번 재작성합니다.

**한계와 다음 측정**

- 30/30은 소규모 규칙 라우팅 데이터셋의 정확 일치율입니다. 별도 미공개 평가셋의 일반화 성능이나 LLM 답변 품질 점수가 아닙니다.
- 항상 모든 에이전트를 선택하는 기준선과의 비교는 계획 선택 비교입니다. 실제 두 시스템의 지연·토큰·비용을 비교한 실험은 아닙니다.
- Critic 재작성 뒤 동일 검증을 다시 수행하지 않습니다. 지속 개선을 입증하려면 원칙 준수·근거 정확성 등의 평가 기준, 사람이 검토한 답변, 수정 전후 품질·지연·비용 비교와 회귀 방지 절차가 필요합니다.
- 현재 테스트는 규칙 경로 중심이며, 모델을 연결한 전체 경로의 품질 검증을 대체하지 않습니다.

## 3. 금융 데이터 파이프라인

**구현됨**

Toss·Mock MyData의 데모 보유내역 또는 방문자가 직접 입력한 보유내역을 공통 포트폴리오로 변환하고 종목 메타데이터를 결합합니다. 보유내역과 독립된 시장 전용 Toss transport로 시세·종목명·환율을 조회하고 원화 평가액을 계산합니다. 계좌 endpoint는 차단하며, 조회 실패 시 예시 시세로 대체하지 않습니다. ETF 구성 비중 계산은 fixture 모드에서만 체험할 수 있고 실제 시장 모드에서는 구성 데이터 미지원 경고를 표시합니다. 정규화 결과와 일부 도구 출력에 Zod 검증을 적용하고 `source`, `asOf`, `retrievedAt`, `isMock`을 전달합니다. 누락 데이터는 경고 또는 도구 오류로 표현합니다.

**범위**

현재 OpenDART·SEC 연동은 공시 제목·유형·날짜·링크 및 구조화 재무 지표를 조회합니다. 공시 본문이나 PDF·HTML을 수집해 텍스트를 추출·정제·청킹·색인하는 파이프라인은 없습니다. 요청 시 수행하는 통합 처리는 구현됐지만, 배치 수집·증분 적재·재처리·데이터 품질 모니터링을 갖춘 운영 파이프라인은 아닙니다.

## 포트폴리오 소개 문구

> 금융 데이터 정규화와 결정론적 계산을 도구로 제공하고, 질문 라우팅·멀티 에이전트 실행·대화 메모리·응답 검증을 연결한 투자 분석 프로토타입을 구현했습니다. 라우팅 평가셋과 회귀 테스트, 실행 Trace로 동작을 검증하며, 공개 데모에서는 데모 또는 직접 입력한 보유자산에 실제 시장 데이터를 결합하도록 구성했습니다. 실제 API 연결 상태와 계산 근거를 화면에서 확인할 수 있습니다.

실제 모델 실행 영상에는 **단순 질문과 복합 질문의 실행 차이 → 도구 입출력 → 후속 질문의 기억 → 검증 및 재작성 여부 → Trace**를 보여주면 각 구현을 확인하기 쉽습니다. 실행되지 않은 단계는 생략 사유와 함께 표시합니다.
